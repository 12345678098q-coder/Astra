# Палитры · Palette Mixer

Открытие: **Инструменты → Палитры · Palette Mixer**. Это инструмент панели,
с отдельной вычислительной частью `engine.py` и интерфейсом `ui.py`.
Настройки сохраняются в `process_options/native_palettes`; открытое состояние
и выбранные по именам источники восстанавливаются с проектом Astra.

## Источники

* Моно: открытые Ha, OIII, SII. Для HOO нужны только Ha и OIII.
  При нулевом третьем столбце матрицы SII можно не выбирать.
* RGB: три канала одного открытого RGB используются как A, B, C.
* RGB Ha/OIII → HOO: Ha=R, OIII=(G+B)/2.
* Два RGB Ha/OIII и SII/OIII: Ha=R первого, SII=R второго,
  OIII — среднее G/B обоих. Кадры должны быть заранее совмещены.

Последние два режима — явно обозначенные приближения для двухполосных
фильтров. Они не измеряют физические эмиссионные линии и не компенсируют
различия спектральной чувствительности фильтров и камеры.

## Оригинальный PaletteMixer.js

Предоставленный пользователем скрипт версии 1.1.0 и его NonModal.jsh
сохранены в `source` без изменений. Исходные файлы на рабочем столе не менялись.
Матрицы всех девяти пресетов перенесены точно:
RGB, HOO, SHO Hubble, HOS, HSO, OSH, Forte, CFHT, Dynamic SHO.
Строки матрицы — выходные R/G/B; столбцы — Ha/OIII/SII или A/B/C.
Dynamic SHO в этом скрипте является фиксированной матрицей, а не
адаптивным нелинейным преобразованием. Правка коэффициента переводит
пресет в «Своя матрица».

Расчёт Astra выполняется float64 вместо float32 PixelMath исходника.
Предусмотрены сохранение диапазона, обрезание в 0…1 и общее линейное
масштабирование всех RGB в 0…1. Последнее используется по умолчанию,
как опция rescale в скрипте. Точная эквивалентность поведения rescale
PixInsight не заявляется. Конечные значения используются при оценке
диапазона; NaN сохраняются в затронутых компонентах, Inf отклоняются.

## Что проверено в AstroWizard

На ПК найден `Desktop/AstroWizard.exe` (упакованная программа, Python 3.14).
В интерфейсе наблюдались режимы Combine Mono Channels: Broadband RGB,
Narrowband SHO, Narrowband HOO, My own mix; описание сообщает о выравнивании
фона. На главной странице также присутствует Two dual-band stacks → SHO.
После остановки пользователем Computer Use дальнейшее управление не выполнялось.
Из предоставленного пользователем скриншота доступны настройки synthetic green,
blend amount, OIII boost, shadow point, highlight reduction, brightness;
сам скриншот имеет заголовок HOO.

Точные формулы Mode1 и других режимов закрытой программы не подтверждены.
Код AstroWizard не включён в Astra, не выполняется и не требуется.
Не заявляется одинаковый результат с AstroWizard. Вместо неизвестных Mode1/Mode2
в Astra применены описанные ниже самостоятельные алгоритмы с понятными именами.

## Настройка SHO/HOO в Astra

Необязательная галочка «Настройка SHO / HOO» включает дополнительные
преобразования для HOO, SHO Hubble и Dynamic SHO. Без неё используется
только матрица. OIII сначала умножается на заданный коэффициент.
Синтетический зелёный заменяет выходной G:

* Линейная смесь: `(1−t)Ha + t·OIII`.
* Экран: `Ha + t·OIII·(1−Ha)`.
* Геометрическая смесь: `max(Ha,0)^(1−t) · max(OIII,0)^t`.

Далее к RGB применяются показатель теней `x^p`, сжатие светов
`x/(1+(k−1)x)` и множитель яркости. При p=k=brightness=1 эти этапы
сохраняют значения; t=.6 по умолчанию. Это нелинейная обработка и требует
исходных значений 0…1 до преобразований. Усиление OIII может дать значения
выше 1; они сохраняются до выбранной обработки диапазона. Отрицательная
смесь при включённой настройке теней отклоняется. Для сырых ADU
используйте базовую матрицу либо сначала явно нормализуйте каналы.

Опциональное выравнивание фона — собственный метод Astra: медианы
выборки до 1024 px на сторону согласуются постоянными аддитивными
поправками к минимальной медиане входных каналов. Пространственный
градиент не удаляется. На кадре с обширной туманностью медианы могут
исказить баланс; по умолчанию функция выключена.

## Результат и предпросмотр

Результат создаётся новым RGB или применяется к явно выбранному RGB.
При применении активная маска целевого изображения ограничивает эффект,
а успешный результат создаёт шаг PAL в истории. Источники и файлы не
перезаписываются автоматически. Новые изображения получают уникальные имена.
Предпросмотр всегда временный, без истории. Изменения автоматически
пересчитываются в фоне. Его предрастяжка фиксируется по первому показу,
чтобы автоподбор не компенсировал цветовые/яркостные изменения; отмена
и повторное открытие пересчитывают её. Смена источника сбрасывает параметры
предрастяжки. Отмена в панели или общем журнале отбрасывает результат.

Тесты проверяют матрицы сравнением с исходным JS в Node, смешивание
каждого пресета, HOO без SII, RGB и двухполосные режимы, формулы зелёного,
тени/света/яркость, диапазон, фон, несовместимость размеров, NaN, отмену,
предпросмотр и его обновление, маску, историю и проект. Сравнение одинаковых
кадров с закрытым AstroWizard не проведено; визуальное качество палитры
на реальном пользовательском наборе не оценено.
