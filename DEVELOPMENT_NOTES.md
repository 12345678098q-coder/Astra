# Astra

В настройках сложения → «Совмещение» доступен автокроп по общей области принятых кадров. Он убирает непокрытые края после регистрации и обрезает изображение вместе с картой COVERAGE. Дополнительная галка разрешает подбор поворота до ±20° для сохранения большей прямоугольной области; поворот применяется только при выигрыше площади более 2%. В панели «Кадрирование» рамку можно поворачивать мышью за круглую ручку над ней; применение сохраняет повёрнутый фрагмент в истории. Там же доступен автокроп уже открытого изображения с галкой «Автоповорот». Для сохранённых FITS используется карта COVERAGE, для файлов без неё автокроп ищет явно пустые края и длинные границы областей с разной глубиной сложения.

Запуск в Windows: `Astra.exe`. Чтобы открыть изображение из Проводника, выберите «Открыть с помощью» → «Выбрать другое приложение» → `Astra.exe` в папке проекта. Windows передаст путь к файлу, и Astra откроет его в новом окне приложения. Можно также перетащить путь в командную строку: `Astra.exe "C:\путь\кадр.fits"`. Запускатор не содержит Python-код или зависимости; рядом должны оставаться `app.py`, папки проекта и `.venv` либо `runtime`. Пересборка запускатора: `powershell -NoProfile -ExecutionPolicy Bypass -File build-support\build-launcher.ps1`.
Язык интерфейса выбирается в **Настройки → Настройки программы → Язык**. Сохраните выбор и перезапустите Astra. Palette Lab использует тот же язык при следующем запуске.

To switch to English, open **Настройки → Настройки программы**, choose **English** under **Язык**, click **Сохранить**, and restart Astra. Palette Lab uses the same preference.

Запуск: start.bat. Проверка: .venv\Scripts\python test_pipeline.py.
Стек: median masters; (light-dark)/normalized(flat-darkflat); Astroalign; нормализация фона; MAD rejection 3.5 sigma и среднее. При числе lights меньше пяти используется среднее без rejection. Экспорт float64 FITS с COVERAGE.
Проверены синтетические звёзды со сдвигами, калибровка, выбросы, FITS/TIFF/XISF и запуск GUI. Реальные серии пока не проверены.
Ограничения: моно, RGB и четыре Bayer-паттерна. Режим «RAW фотоаппарата» принимает CR2, CR3, NEF, ARW, DNG, RAF, RW2, ORF и PEF через LibRaw; читает сырую матрицу, вычитает уровни чёрного, калибрует до дебайеризации. Поддерживается стандартный Bayer. Трёхканальные TIFF/FITS можно открыть для просмотра, но в меню сложения отдельного режима для них нет. Пользователь проверяет соответствие выдержек, температуры, gain, offset, фильтра и камеры. Проверка метаданных не реализована, dark не масштабируется. Flats требуют dark flats. Совмещённые кадры и мастер-кадры хранятся во временном дисковом кеше; одна исходная фотография и её обработка всё ещё требуют оперативной памяти. Для больших серий нужен свободный диск. Нет отмены, локальных весов, детектора спутников и коррекции дисторсии. Ошибка совмещения останавливает расчёт. Открывается первое изображение FITS/XISF. Кубы не поддерживаются. Метаданные/WCS в экспорт не переносятся. Авторастяжение влияет только на просмотр.
Развитие: дисковый кеш и тайлы, калибровка CFA до дебайеризации, проверка метаданных, веса по шуму и резкости, маски спутников, история обработки и сохранение проекта. Превосходство над DSS не измерялось.
Зависимости зафиксированы в requirements.txt; библиотека xisf распространяется под GPLv3.


Обновление: вычисления CPU / Auto / NVIDIA CUDA для обычного сложения (медиана, среднее, MAD). Регистрация, калибровка и drizzle работают на CPU. Для CUDA нужны CuPy и CUDA runtime. Auto проверяет доступность CUDA при запуске и использует CPU при недоступности. Drizzle STScI: квадратное ядро, масштаб 1–3, pixfrac 0.1–1; выполняется по исходным откалиброванным кадрам и преобразованиям регистрации. Использует взвешенное накопление без sigma rejection; COVERAGE в этом режиме содержит веса. Для цветных кадров используется обычная дебайеризация до drizzle, это не CFA drizzle. Единицы яркости сохраняются (iscale=1), сумма пикселей при увеличении масштаба растёт. Субпиксельный dithering необходим для выигрыша в разрешении. Большие масштабы повышают расход RAM и диска.

CPU-установка: pip install -r requirements.txt. CUDA-ускорение для NVIDIA устанавливается отдельно в `optional/cuda/site-packages`: `.venv\Scripts\python.exe -m pip install --no-deps --target optional/cuda/site-packages -r requirements-cuda.txt`. В меню «Настройки → Поддержка NVIDIA GPU» доступна команда с абсолютными путями для текущей установки. Папку `optional/cuda` не включать в базовые архивы и установщики; политика находится в `build-support/package-policy.json`. Поле «Вычисления сложения» управляет только финальным средним/медианой/MAD; это явно не ускоряет весь конвейер. Проверки разработки: test_pipeline.py, check_new_stack.py (последний требует CUDA). Горячие/холодные пиксели перенесены во вкладку Калибровка. Настройки сигмы видны только для MAD и выключенного Drizzle.

StarNet: Инструменты → Отделение звёзд — StarNet. Три режима: линейное фото (--linear), применить текущую предрастяжку, уже растянутое фото [0,1]. Минимум 512×512, моно/RGB. Результат сохраняется отдельно в FITS/TIFF; по желанию рядом сохраняется положительная разность со звёздами (_stars). Открытое изображение не заменяется. Подготовка и экспорт вынесены в starnet.py. CLI 2.6.2 загружен напрямую с https://starnetastro.com/cli-tools/starnet/; SHA-256 архива fbd5c7bdbbbee0cdbabf101b2c7ac2af3d33e3c477f9585f38f98b882f1551a0. StarNet требует принятия лицензии перед использованием. tools/starnet — локальная установка, не включать её в распространяемую сборку без разрешения правообладателя. Для установки на другом компьютере скачайте официальный архив и распакуйте целиком в tools/starnet.

Обновления внешних инструментов: Настройки → Обновления инструментов и ИИ-моделей. Для каждого инструмента доступны автоматическая проверка при запуске/каждые 24 часа и отдельное автообновление (изначально выключено). Кнопки проверяют и обновляют все три инструмента. StarNet использует официальный JSON feed и SHA-256 архива, новая версия активируется после проверки запуска. GraXpert закреплён на 3.1.0rc2; модели фона, шумоподавления и деконволюции объекта/звёзд проверяются через официальный сервер, указанный в его дистрибутиве. Модели сохраняются в стандартный локальный каталог GraXpert. RC-Astro использует update, update --install и download-models для лицензированных продуктов; установщик может потребовать действия пользователя. Обновления идут в рабочем потоке с журналом. Не распространяйте локальный каталог tools/starnet вместе с программой без разрешения правообладателя.
Размер окна сложения меняется за уголок справа внизу; окна просмотра используют системные рамки MDI.

Проверка перед сложением: выбранные файлы читаются в отдельном потоке до построения мастеров. Проверяются размеры (включая число каналов), выдержки Lights/Darks и Flats/Dark flats по EXPTIME/EXPOSURE (в том числе FITSKeywords XISF). При несовместимых дарках или неизвестной выдержке предлагается запуск без Darks; файлы остаются в списке. Несовместимые Lights/Flats/Dark flats останавливают запуск с подробностями. Допуск выдержки: 0.01%, абсолютный минимум 1 мкс. Для форматов без доступных метаданных выдержки проверка явно сообщает об ограничении. Тесты: python -m unittest test_validation -v.


Структура исходников:
- app.py — сборка главного окна, меню, тема, открытие и сохранение изображений.
- modules/stacking/ — модуль сложения: ui.py (панель), files.py (категории/списки), settings.py (настройки), preview.py (предпросмотр), controller.py (запуск/прогресс), workers.py (фоновые задания), engine.py (вычисления).
- processes/stretch.py — экранное растяжение и его настройки.
- processes/graxpert.py и processes/rcastro.py — адаптеры команд соответствующих программ; external.py — общий запуск и чтение результата.
- processes/starnet/ — интерфейс и обработка StarNet.
- processes/tool_updates.py и tool_settings.py — обновления внешних инструментов и их настройки.
- core/image_io.py — чтение изображений и дебайеризация.
Новые модули размещать в modules/<name>/, новые процессы в processes/<name>.py или одноимённой папке. Не добавлять их реализацию в app.py.


### Предпросмотр, навигация и мастер-кадры
- Предпросмотр выбранного кадра находится внутри модуля под категориями. Первый добавленный кадр выбирается автоматически. Bayer и авторастяжка применяются только к просмотру.
- Модуль имеет стандартную рамку Qt, перемещается за заголовок и меняет размер за края. Закрытие скрывает модуль, сохраняя списки.
- Каждая категория отдельно запоминает последнюю папку добавления файлов.
- Готовый мастер: выберите категорию, затем «Действия со списком → Загрузить готовый мастер». TIFF с меткой DSSMaster и FITS с MASTER=T распознаются также при обычном добавлении. Имя файла не определяет его назначение. Нельзя смешивать мастер с исходниками одной категории. Пресеты сохраняют явно выбранный статус мастера.
- Во время сложения новые мастеры автоматически сохраняются в AstraMasters рядом с первым light, в отдельной папке запуска. Путь и сохранение меняются в настройках калибровки. Создаются MasterDark.tif, MasterDarkFlat.tif, MasterFlat.tif без дебаера и растяжки. Мастер-флет уже откалиброван; повторно dark flat из него не вычитается.
- Экспорт: float32 TIFF, DSSMaster (50007), DSSNumberOfFrames (50000), DSS exposure (50008), CFA (50006/50009), ISO/gain при наличии. Значения dark сохраняются в исходных единицах, без обрезания и растяжки. Диапазон TIFF берётся из DATAMIN/DATAMAX исходного FITS; при их отсутствии предполагается ADU 0…65536. Для нормированных float-FITS необходимо корректно указать DATAMIN/DATAMAX в исходных файлах; нельзя смешивать ADU и нормированные калибровочные данные. Старые DSS float-TIFF с диапазоном 0…1 на входе преобразуются в ADU.
- В DSS добавляйте мастеры в соответствующие категории. Эта схема без bias: dark и dark flat включают смещение. Не добавляйте bias к этим же мастерам. Совместимость тегов сверена с исходным кодом DSS; численный повторный импорт проверен синтетическими тестами. Полный прогон в установленной DSS и обмен мастерами камерного RAW между разными декодерами пока не проверены (могут отличаться чёрный уровень, обрезка и шкала).
- Главный просмотр: колесо масштабирует вокруг курсора; удержание левой кнопки перемещает изображение. Правый клик → «Вписать в окно» или «Автопредрастяжка». Растяжка не меняет исходные пиксели и не сбрасывает масштаб.
- Файлы: core/image_view.py — навигация; core/master_io.py — обмен TIFF; modules/stacking/masters.py — распознавание и проверка мастеров.
- Проверки: test_masters.py, test_workspace.py, test_validation.py, test_pipeline.py.

### Автоматический выбор ресурсов
По умолчанию в сложении включён автоподбор ресурсов. Перед запуском измеряется доступная физическая память; сохраняется дополнительный резерв 15% общей ОЗУ (от 512 МБ до 4 ГБ). На новую задачу планируется не более 65% доступной памяти. Это консервативная оценка, а не жёсткая квота ОС.
Число потоков вычислительных библиотек ограничено примерно 75% доступных CPU и бюджетом памяти; минимум один поток. Размер входного блока всегда подбирается автоматически по числу кадров, размеру изображения, доступной RAM/VRAM и числу параллельных блоков; ручного поля нет. Размер пересчитывается между партиями блоков. Проверяются оценка памяти совмещения и место для дискового кеша. Для FITS/TIFF оценка выполняется до декодирования; для RAW/XISF декодеры ещё могут выделять память до проверки полного кадра.
В автоматическом режиме CUDA выбирается при работоспособном backend и достаточной свободной видеопамяти. Бюджет блока учитывает VRAM, нехватка памяти CUDA при интеграции переключает дальнейшую обработку на CPU. Ручной выбор device доступен после отключения автоподбора; размер блока остаётся автоматическим; базовые проверки чтения сохраняются.
GraXpert, RC-Astro и StarNet получают ограничение CPU affinity (где поддерживается), пониженный приоритет в Windows и переменные числа потоков. Перед запуском используется предварительная оценка 12 размеров изображения; точная память ИИ-моделей зависит от инструмента. Жёстких лимитов RAM/VRAM для внешних процессов нет. Одновременный запуск тяжёлых обработок внутри одного экземпляра Astra запрещён, интерфейс и просмотр доступны. Политика вынесена в core/resources.py для повторного использования новыми модулями.


### Ускорение создания мастеров
Калибровочные исходники декодируются один раз на категорию при создании мастера. Подготовленные float32 данные сохраняются во временный дисковый кеш; медиана/среднее вычисляются блоками (до четырёх параллельных CPU-блоков при достаточной памяти). Кеш группы закрывается и удаляется после создания мастера, в том числе при ошибке. Проверка файлов до запуска может дополнительно читать исходники. Лайты по-прежнему калибруются и совмещаются последовательно; CPU-интеграция блоков параллельная, GPU-интеграция последовательная.
В журнал добавлены время чтения/объединения каждого мастера, время калибровки и совмещения, интеграции и всего стека. Старый сохранённый параметр block_mb больше не используется.
Синтетический CPU-бенчмарк benchmarks/stacking.py (18 калибровочных FITS 768×1024, 3 light, без регистрации): 222 → 18 декодирований калибровочных исходников, 1.201 → 0.551 с, пик RSS процесса 105.8 → 131.3 МБ. Численные результаты совпали (rtol=1e-6, atol=1e-5). Это измерение конкретного теста; скорость реальных серий зависит от формата, диска, размера кадров и регистрации. Для повторения бенчмарка --baseline должен указывать на сохранённый engine.py до изменения.


### Настройки открытых инструментов
Правая полоса открытых инструментов отделена вертикальной линией; выбранная кнопка подсвечивается. Настройки находятся слева. Параметры каждого процесса сохраняются в QSettings отдельно; «По умолчанию» сбрасывает их. Неоткрытые инструменты не добавляются в полосу.
- GraXpert: сглаживание и тип коррекции фона, вывод модели фона, сила шумоподавления/деконволюции, PSF, размер партии ИИ, GPU и версия модели. Поддержаны все четыре операции меню.
- BXT: звёзды, ореолы, авто/ручной PSF, туманность, коррекция аберраций, планетный режим.
- NXT: яркостный/цветовой шум на малых/больших масштабах, граница масштабов и итерации.
- SXT: отдельный слой звёзд и unscreen. У RC-Astro также доступны устройство, перекрытие и версия модели. Вывод всегда float32.
- StarNet: панель содержит режим входа, слой звёзд/unscreen, шаг обработки, 2×, порог теней, целевой фон и защиту светов. Файл результата и согласие с лицензией задаются здесь же. Слой звёзд открывается отдельно; основной результат записывается в историю исходного снимка. Лицензия показывается отдельным диалогом. Прерывание выполняется кнопкой «Остановить».
Формы и валидация: processes/options.py, processes/option_form.py. Передача параметров проверена по installed RC-Astro 2.6.10 и StarNet 2.6.2 --help, парсеру GraXpert main.py и установленному cmdline_tools. test_process_options.py проверяет сохранение, зависимости полей, команды и обработку двух результатов с имитацией CLI; это не тест качества нейросетей.
Источники: https://github.com/Steffenhir/GraXpert/blob/main/graxpert/main.py ; https://www.rc-astro.com/stand-alone-rc-astro-tools/ .

### Снимки состояния изображения
История внутри фото показывает снимки снизу вверх: исходное внизу, новые выше, с краткими обозначениями инструментов. Щелчок восстанавливает снимок; Ctrl+Z / Ctrl+Shift+Z переходят между состояниями. Перетащите снимок на свободное место рабочей области, чтобы открыть независимую копию. Если всё место занято, уменьшите окно за нижний левый угол. Контекстное меню снимка также позволяет открыть копию или удалить его вместе со всеми более новыми снимками (исходное сохраняется).

F2 или контекстное меню фото переименовывает окно. «Правка → Разделить RGB на изображения» создаёт независимые монохромные R, G и B. Эти команды доступны и в контекстном меню фото. Журнал выделен рамкой и имеет нижний левый угол изменения размера. Внутренний MIME-формат снимков подготовлен для будущих получателей в инструментах и скриптах; сейчас перенос поддерживает рабочая область.

Проверки: `python -m unittest test_checkpoints test_process_options`.

### Автовыравнивание фона (BN)
«Инструменты → Автовыравнивание фона» открывает настройки силы коррекции, доли тёмных участков, сетки выборки и порога исключения звёзд. Инструмент оценивает общий фон RGB по устойчивым медианам участков и добавляет постоянные поправки каналам. Он предназначен для линейных RGB-изображений; пространственные градиенты обрабатываются GraXpert. Отрицательные значения сохраняются, контраст объектов внутри канала не меняется. Результат сохраняется в истории как BN; обработка идёт в отдельном потоке с журналом и проверкой доступной памяти.

Правило разработки: каждый новый инструмент сразу получает доступные пользователю настройки, сохранение параметров, сброс к значениям по умолчанию и запись результата в историю, если меняет пиксели.

Проверки инструмента: `python -m unittest test_background_tool`.

### Кадрирование (Crop)
«Инструменты → Кадрирование» включает выделение области левой кнопкой прямо на фотографии; средняя кнопка сохраняет перемещение просмотра. В настройках доступны свободные пропорции, 1:1, 3:2, 4:3, 5:4, 16:9, 16:10, 2:1, 21:9 и A4, портретная/альбомная ориентация, координаты и размеры в пикселях. Формат и ориентация запоминаются. Кнопки позволяют центрировать и сбросить область. «Применить кроп» создаёт состояние Crop в истории; Ctrl+Z возвращает полный кадр. При переключении на другой инструмент выделение скрывается. Проверка: `python -m unittest test_crop`.

### Установка и обновление ASTAP
`install.bat` создаёт окружение Python, устанавливает зависимости Astra, затем загружает официальный ASTAP CLI для Windows x64 и каталог D50. Уже установленную копию в Program Files он не заменяет. Управляемые файлы находятся в `tools/astap`; версии CLI переключаются через active.json после проверки запуска. Каталог D50 проверяется по SHA-256 официального архива. При отсутствии сети рабочая копия сохраняется; ошибка установки отображается в журнале обновлений.

При запуске и раз в сутки Astra проверяет ASTAP и автоматически устанавливает новую версию (это можно отключить в настройках обновлений). Если ASTAP отсутствует, первая проверка устанавливает CLI и каталог. Плагин автоматически использует управляемую версию; вручную выбранный нестандартный путь остаётся доступным. В панели астрометрии также есть кнопка установки/обновления. Для первого скачивания D50 требуется около 860 МБ трафика и дополнительное место для распаковки. Источники: https://www.hnsky.org/astap.htm и официальный проект ASTAP на SourceForge.

### Закрепление инструментов
В контекстном меню кнопки открытого инструмента включите «Закрепить при запуске». Закреплённые инструменты открываются при запуске с сохранёнными параметрами, без автоматического выполнения обработки. Звёздочка в подсказке отмечает закрепление. Закрытие панели не снимает закрепление; для этого выключите пункт в контекстном меню.

Проверка: `python -m unittest test_pins_astap_updates test_process_options test_checkpoints test_crop`.

### Проекты Astra
В меню «Файл» появились «Сохранить проект» (Ctrl+S), «Сохранить проект как…» (Ctrl+Alt+S) и «Открыть проект…» (Ctrl+Alt+O). Формат `.astra` содержит изображения без потерь, все снимки истории и текущую позицию в ней, WCS текущего снимка, названия и расположение окон, скрытые окна, масштаб просмотра, параметры предрастяжки и кропа, открытые/закреплённые инструменты и их параметры, панель быстрых кнопок, окно модуля сложения, настройки сложения, списки кадров и журналы. Работающие процессы в проект не сохраняются: перед сохранением нужно завершить обработку.

Изображения и история встроены в файл проекта. Исходные кадры из списков сложения сохраняются ссылками на файлы; при их перемещении потребуется восстановить пути. Внешние программы и ИИ-модели не упаковываются в проект и устанавливаются отдельно штатным механизмом Astra. Проект может занимать много места: каждый снимок истории хранится без потерь. Запись происходит в отдельный временный файл, который заменяет предыдущий только после успешного сохранения. Открытие проверяет архив и распаковывает историю на диск; при недостатке памяти или свободного места выводится ошибка.

Проверки: `python -m unittest test_projects` (история назад/вперёд, несколько окон, параметры инструментов, кадры сложения, повреждение архива, сбой записи, пустой проект). Отдельно проверен полный путь команд меню через фоновые задачи сохранения/открытия.

### Подписи объектов в астрометрии
В «Плагины → Астрометрия · ASTAP» добавлена секция «Подписи объектов». После решения координат (или открытия FITS с WCS) нажмите «Показать / обновить подписи». Astra проецирует каталог ASTAP `deep_sky.csv` на изображение: именованные звёзды и объекты глубокого космоса, каталожные контуры, основные или альтернативные названия. Настраиваются цвет, размер текста и максимальное число объектов; есть скрытие разметки, сброс настроек и экспорт отображаемого фото в PNG с подписями. PNG использует текущую предрастяжку, исходные FITS-пиксели не меняются.

Каталог подписей копируется из установленного ASTAP или извлекается установщиком из официального архива ASTAP. Разметка и её видимость сохраняются в `.astra`. После изменения пикселей/геометрии существующая WCS и подписи сбрасываются, чтобы не отображать неподтверждённую привязку. Линии созвездий в этой версии не реализованы. Каталожные размеры объектов не являются выделением их границ по пикселям фото.

Справка ASTAP: https://www.hnsky.org/astap.htm (команда -annotate относится к полной GUI-версии; интеграция Astra использует WCS от CLI и собственное отображение). Проверки: `python -m unittest test_annotations test_projects`.

### Новые инструменты обработки
Все новые команды находятся в меню **Инструменты**, а их настройки открываются в правой панели. Вычислительная часть: `processes/native/processing.py`, безопасный интерпретатор: `pixelmath.py`, файловая очередь: `batch.py`; интерфейс: `ui.py`, `workflows.py`; фоновые задачи: `jobs.py`.

* **Гистограмма и растяжение (HT)**: общий канал и R/G/B, точки чёрного/белого, MTF-полутона и кривая с редактированием узлов мышью или записью `0:0;0.25:0.5;1:1`. Общая передача применяется первой, затем индивидуальные RGB. Гистограмма берётся из ограниченной выборки; вертикальная ось логарифмическая. Кнопка диапазона устанавливает чёрную/белую точки в единицах исходных данных. Результат нормируется в 0…1 с обрезанием за пределами точек. При применении предрастяжка просмотра отключается. Предпросмотр изолирован от исходного массива; применение создаёт состояние HT, отмена убирает предпросмотр.
* **Цветокалибровка (CC)**: пользователь рисует прямоугольник фона мышью, подтверждает его или задаёт координаты; нейтрализация использует медианы конечных пикселей ROI. Ручные коэффициенты R/G/B меняют баланс всего кадра. Операция не обрезает диапазон и сохраняет отрицательные значения. Калибровка по звёздам пока не реализована.
* **Маски**: диапазон яркости и плавность в единицах данных либо звёздная маска с порогом, радиусом обнаружения и размером выделения. Доступны создание, просмотр, инверсия, включение/выключение и копирование маски в отдельное изображение. Белое разрешает обработку, чёрное защищает. Маски поддерживают HT и CC; маска и включённость сохраняются в проекте. При изменении размеров фото несовместимая маска отключается и удаляется. Маски не создают шаг изменения пикселей исходного изображения.
* **PixelMath (PM)**: открытые фото выбираются по списку `I1 = имя`, двойной клик вставляет ссылку/канал. Поддержаны арифметика `+ - * /`, скобки, унарные знаки, `min`, `max`, `clip`, `abs`, `sqrt`, каналы `.R/.G/.B/.L`. Размеры проверяются заранее, моно допускается совмещать с RGB одного размера. Используется AST с разрешённым набором узлов, без eval/exec, индексации, произвольных атрибутов и импорта. Деление на ноль и недопустимый корень дают ошибку. Результат создаётся отдельным изображением, float64, без скрытого clipping. После изменения исходных открытых фото список нужно обновить.
* **Анализ кадра (Stats)**: размеры, каналы, min/max, медиана яркости, робастная оценка высокочастотного шума, число звёзд, приблизительный FWHM по моментам и число неконечных пикселей. Можно сравнить открытые фото либо выбрать исходные файлы. Числовые столбцы сортируются. Порог и радиус обнаружения настраиваются. Эти показатели ориентировочные и зависят от структуры объекта, масштаба и настроек; FWHM не заменяет точное PSF-моделирование. Лимит детектора 50000 кандидатов, размер в пикселях.
* **Пакетная обработка (Batch)**: последовательность HT и CC с копией текущих настроек, изменение порядка, просмотр параметров двойным кликом, выбор файлов/папки/формата FITS или TIFF/префикса/суффикса. Маски отдельных изображений не используются в пакете; ROI одинаков для всех файлов. Несовместимый файл записывается в журнал, остальные продолжают обрабатываться. Имя результата резервируется без перезаписи; при совпадении добавляется номер. Сохраняются float64. Отмена происходит между операциями; уже записанные результаты остаются на диске.

Длительные операции работают в QThread с общим журналом, прогрессом и проверкой доступной памяти. Полные массивы остаются в памяти для некоторых вычислений: при нехватке памяти инструмент откажется от запуска; обработки через диск для этих инструментов пока нет. Отмена внутри одного вызова NumPy/SciPy ожидает завершения этого вызова. Кривые используют линейную интерполяцию узлов. Неконечные пиксели сохраняются в HT и CC, исключаются из статистики и защищаются при создании маски. FITS/TIFF float64 теперь читаются без принудительного приведения к float32.

Проверки: `python -m unittest test_native_tools test_projects test_checkpoints test_process_options test_crop test_background_tool test_annotations test_pins_astap_updates test_validation test_masters test_stacking_resources` — 36 тестов. Проверены также английские панели, редактирование отдельных каналов, запуск пакета, таблица анализа и восстановление настроек инструментов и очереди из проекта. Визуальная проверка offscreen ограничена отсутствующими шрифтами тестовой среды; реальное отображение текста в Windows требует обычного запуска приложения.

### Коррекция горячих и холодных пикселей (CPC)
«Инструменты → Горячие и холодные пиксели» позволяет отдельно включать горячие и холодные выбросы, задавать порог 2…50 σ, радиус соседей 1…2 и 1…3 прохода. Режим сырого Bayer обрабатывает четыре позиции матрицы независимо и предназначен для 2D-кадров до дебаера; паттерн не требуется, поскольку цвета не смешиваются. RGB обрабатывается поканально. Пиксель заменяется медианой соседей при превышении порога относительно локального MAD и общей оценки шума. Диапазон не нормируется, NaN/Inf и край шириной радиуса сохраняются. Очень мелкие звёзды могут быть приняты за дефекты: используйте высокий порог, предпросмотр и защитную маску.

Поддержаны предпросмотр, отмена, сброс, применение к активному изображению с записью CPC в историю, маски и пакетная обработка. Настройки сохраняются. Для отключённых переключателей инструмент возвращает неизменённую копию. Проверки: `python -m unittest test_defects_tool test_native_tools test_projects test_process_options` — 19 тестов, включая RGB, CFA, защиту маской, нечисловые пиксели, сохранение протяжённого источника и GUI-сценарий предпросмотр/применение/отмена по истории.

### Трёхточечная растяжка и временный предпросмотр
В HT на гистограмме появились три перетаскиваемых маркера: чёрная точка, полутона и белая точка. Выбор «Общий / R / G / B» меняет редактируемый набор. Общая передача применяется первой, затем индивидуальные каналы: все неприменённые настройки входят в один результат. Настройки каналов не сбрасываются при переключении. RGB-точки задаются в нормированном диапазоне после общей передачи.

Кнопка «Авторастяжка» — переключатель: при включении подбирает чёрную/белую точки по процентилям и MAD, полутона — под целевую медиану фона. При выключении возвращает сохранённые до включения ручные настройки. Ручное изменение точки отключает флаг авто, сохраняя рассчитанные значения как основу. Авторастяжка HT меняет только настройки до применения; предрастяжка просмотра остаётся отдельной функцией с собственной кнопкой включения/выключения. Ручная растяжка доступна через HT.

Предпросмотры HT, CC, CPC, маски и PixelMath, а также кропа, BN, GraXpert, RC-Astro и StarNet открываются во временном немодальном окне без истории. Исходные документы и проект не получают неприменённых пикселей. HT/маски показываются в диапазоне 0…1; остальные могут использовать предрастяжку просмотра. Окно можно закрыть независимо. Отображение предпросмотра ограничено 2400 пикселями по стороне, численные данные результата сохраняют исходное пространственное разрешение. В HT/CC/CPC изменение настроек обновляет открытое окно после короткой задержки.

Кнопки сброса, отмены, предпросмотра и применения перенесены в закреплённую нижнюю часть панелей под прокручиваемыми настройками: предпросмотр слева, применение справа. Для анализа и пакетной обработки используются их команды запуска, без искусственного предпросмотра изменённых пикселей. Проверки: 40 ранее существующих тестов и 2 сценария `test_stretch_preview` (совместная передача общего/RGB, авто вкл/выкл, отсутствие истории и изменений исходника, порядок кнопок, целевая яркость).


### Коррекция смаза / Motion correction

Инструменты → Коррекция смаза (MC) работает с открытым одиночным кадром или результатом сложения. По умолчанию рекомендуется сначала оценить линейный стек: выше отношение сигнал/шум. Для меняющегося между кадрами смаза доступна необязательная коррекция lights в «Настройки сложения → Смаз», после калибровки/дебаера и перед совмещением. По умолчанию отключена; мастера и режим звёздных треков не затрагиваются. Не используйте оба этапа последовательно без проверки.

Алгоритм: регуляризованная обратная фильтрация с линейным PSF, сохранением постоянного уровня и смешиванием с оригиналом. Длина 0–20 пикселей; угол 0° вправо, 90° вниз; защита от усиления шума и сила коррекции. FFT выполняется по блокам 512×512 с перекрывающимся отражённым окружением, каналы RGB последовательно. Результат float64 без растяжки или отсечения яркости; стек сохраняет существующий float32-конвейер. Отрицательные значения допустимы. Возможны ореолы и усиление шума. NaN/Inf и прилегающая область остаются неизменными.

Автооценка использует анизотропию моментов звёзд при предположении исходно круглой формы. Анализируются до девяти областей 512×512 в исходном разрешении. Требуется минимум пять изолированных подходящих звёзд с согласованными направлением и длиной; это приблизительная оценка, не отделяющая ведение от оптических аберраций. Для ненадёжной оценки одиночный инструмент показывает ошибку, а стек оставляет кадр без коррекции и пишет причину в лог. Не поддерживаются длинные дуги, вращение поля, сложная траектория и восстановление пересвеченных данных.

Предпросмотр открывается отдельно без истории; применение создаёт checkpoint MC и поддерживает маску и Undo. В сложении: «Действия со списком → Коррекция смаза выбранного light» открывает полноразмерный кадр с выбранным дебаером в рабочей области; мастера при таком открытии не применяются, исходный файл не изменяется. Настройки RU/EN, сохраняются в программе и проекте. Старые проекты получают новые параметры с выключенной коррекцией.

Проверка: `python -m unittest test_motion`. Синтетический смаз, автооценка, уменьшение ошибки восстановления, границы блоков против полного FFT, RGB/моно, фон/NaN/Inf, маска, отмена, недопустимые параметры, порядок обработки lights, исключение треков, отдельный предпросмотр, история/Undo и открытие одиночного CFA-кадра. Качество на реальных кадрах пользователя ещё не оценено.


### BXT: автонастройка Astra

В BlurXTerminator добавлен переключатель «Автонастройка по изображению», скрывающий ручные параметры. Перед запуском или предпросмотром Astra в фоне анализирует до девяти окон 512×512 в исходном разрешении: ищет звёзды, оценивает приближённый FWHM, эксцентриситет и отношение сигнала звёзд к шуму. По этим измерениям консервативная эвристика выбирает силу для звёзд и протяжённых объектов, снижая её при шуме, мелких или вытянутых звёздах. При достаточном покрытии звёздами и согласованности размеров включается локальный Automatic PSF BXT, иначе используется измеренный общий диаметр PSF (до 8 px). Ореолы не меняются, планетный режим отключён, ресурсы выбираются автоматически. Требуется минимум пять подходящих звёзд; при недостатке данных обработка не запускается и предлагаются ручные настройки. Результат анализа и все выбранные параметры выводятся в журнал. Ручные настройки сохраняются отдельно и возвращаются при отключении галочки.

Это эвристический подбор параметров Astra, а не собственная функция автооптимизации RC Astro и не гарантия оптимального результата. Предназначен для линейных изображений со звёздами; автоматически определить, растянуты ли данные, достоверно нельзя. Алгоритм не меняет растяжку, размер или исходные данные при анализе. Подбор проверен на синтетических звёздах, зависимость силы от шума и фоновой передаче параметров; качество результата на реальных пользовательских кадрах ещё не оценено. Официальное описание параметров: https://www.rc-astro.com/blurxterminator-technical-manual/ .


### Коррекция краёв (EDGE, экспериментальная)

Инструменты → Коррекция краёв. Один параметр «Сила, %», предпросмотр, сброс, отмена и история. Требует установленный и активированный BlurXTerminator. BXT с Automatic PSF выполняет локальную коррекцию аберраций и умеренную деконволюцию (stars .25, nonstellar .2, halos 0); Astra смешивает восстановление по плавной эллиптической карте расстояния от центра: центральные 35% радиуса не меняются, на границе и углах достигается заданная сила. Расчёт смешивания в фоне блоками 128 строк, учитывает активную маску и сохраняет неконечные пиксели. Не растягивает данные. Предназначен для линейных RGB/моно до удаления звёзд; не повторять поверх уже применённого BXT без проверки. При асимметричном кропе геометрический центр может не совпадать с оптическим. Это новая схема применения существующего BXT, не самостоятельная модель деконволюции Astra. Сильный расфокус, насыщенные звёзды и утраченные детали не восстанавливаются гарантированно. Численные проверки смеси/маски/центра и UI с подменённым BXT выполнены; реальное качество на пользовательских кадрах ещё не проверено. Основание: https://www.rc-astro.com/blurxterminator-technical-manual/ .


### Исправление косметической коррекции готовых фото

Окружение дефекта теперь оценивается кольцом за пределами его ядра. Это помогает убирать цветные пятна 3×3 после дебаера, которые прежняя медиана ближайших соседей принимала за часть фона. По умолчанию: порог 6σ, радиус дефекта 2, один проход; старые настройки панели однократно переводятся на эти значения. Радиус 1–4, окружение на один пиксель шире. Оценка шума использует соседние исходные пиксели, без сравнения далёких отсчётов прореженного изображения. Большие связанные области и участки с согласованным ореолом сохраняются как возможные звёзды. Не гарантируется различение крайне мелких звёзд и дефектов, размазанных одинаковым образом; проверяйте предпросмотр и используйте маску при необходимости. Края шириной radius+1 и NaN/Inf сохраняются. Добавлены отмена между блоками, прогресс и число фактически изменённых горячих/холодных пикселей с учётом маски (RGB-позиция считается один раз для каждого типа). Счётчик виден в панели и журнале. Проверены пятна после дебаера, шумный фон, небольшие гауссовы звёзды, маски, раздельные переключатели и Undo. Реальный проблемный кадр пользователя пока не предоставлен.
