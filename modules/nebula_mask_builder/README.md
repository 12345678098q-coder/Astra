# Nebula Mask Builder for Astra

Адаптация предоставленного пользователем NebulaMaskBuilder.js 1.2 для
PixInsight. Исходники сохранены в `source/NebulaMaskBuilder.js` (1.0) и
`source/NebulaMaskBuilder-1.2.js` (1.2).
PixInsight для работы адаптации не требуется. Код JavaScript не исполняется
при обычной работе Astra; интерфейс перенесён на PySide6, вычисления — NumPy/SciPy.

Открытие: **Плагины → Nebula Mask Builder**. Это отдельное перемещаемое и
изменяемое по размеру окно, а не страница панели инструментов.

1. Выберите открытый RGB-кадр.
2. По очереди выберите классы фона, Hα и OIII и отметьте примеры щелчками.
   При необходимости отметьте звёзды/прочее, чтобы они конкурировали с туманностью.
3. Настройте радиус образцов, чувствительность и сглаживание масок.
4. Проверьте выбранный класс через предпросмотр и нажмите «Создать маски».

ЛКМ добавляет круговой образец, ПКМ удаляет ближайший образец текущего класса.
Колесо увеличивает относительно курсора; средняя кнопка или Ctrl + перетаскивание
перемещают изображение. Предрастяжка изменяет только просмотр. Классификация
всегда использует исходные RGB-значения. Для каждого из первых трёх классов
нужен хотя бы один образец с конечными пикселями. Параметры имеют подсказки.

Результаты: `Background_mask`, `Ha_mask`, `OIII_mask` и, по галочке, `Stars_mask`.
Звёздные образцы участвуют в классификации независимо от этой галочки.
Имена существующих изображений не перезаписываются — добавляется суффикс.
Получаются отдельные монохромные изображения float32 в диапазоне 0…1,
доступные для сохранения стандартной командой Astra. Исходное изображение
и его история не меняются. Временный предпросмотр истории не имеет.

Образцы сохраняются по изображениям в проекте Astra; окно, выбранный кадр
и класс также восстанавливаются. После изменения данных кадра образцы
сбрасываются, чтобы не обучаться на устаревшем содержимом. Параметры сохраняются
в настройках. Расчёт выполняется в фоне с прогрессом и отменой, включая кнопку
в общем журнале. Закрытие окна запрашивает отмену его текущего расчёта.

## Соответствие оригиналу

Сохранены шесть цветовых признаков, их веса, объединённая стандартизация,
регуляризованная ковариация классов, расстояния Махаланобиса и softmax
от отрицательного корня расстояния. Пределы — 500 кругов на класс,
16000 обучающих пикселей на класс, 100 Мп на изображение.
Неопределённые пиксели получают фон=1, остальные классы=0 до сглаживания.
Отрицательные RGB при вычислении признаков приравниваются к нулю.

Отличия: NumPy использует другое численное обращение матрицы; выборка свыше
16000 пикселей воспроизводима вместо Math.random; объединение кругов ограничено
2 миллионами пикселей на класс для контроля памяти. Гауссово сглаживание
использует тот же радиус ядра, но отражённые границы SciPy, которые могут отличаться
от PixInsight. Предрастяжка просмотра использует существующий алгоритм Astra.
Маски классифицируют цветовые примеры, а не физически выделяют спектральные линии.

Проверки: сравнение несглаженных масок с математической частью исходного JS
на одинаковом RGB-кадре и образцах (погрешность ≤1e-6); диапазон и сумма масок;
NaN, отсутствие образцов, моно, отмена; щелчки в окне, предпросмотр, публикация
масок, неизменность исходной истории и сохранение/загрузка проекта.

## Возможности версии 1.2

Кнопка AUTO создаёт маски без ручных образцов; выбранная палитра применяется
только к AUTO. HOO ищет тёплый Hα и холодный/белый OIII, оценивает фон
и шум и разделяет два неотрицательных компонента. SHO предполагает
R=SII, G=Hα, B=OIII и строит статистический классификатор по автоматически
найденным образцам. При недостатке цветового контраста AUTO предлагает
ручную разметку. Ручные образцы сохраняются, но в AUTO не используются.
Чувствительность не влияет на AUTO HOO.

SII — пятый класс и отдельная SII_mask; он публикуется при наличии образцов
или в AUTO SHO. Существующий четвёртый класс Stars / Other сохранён;
AUTO его не выделяет. Старые проекты с четырьмя классами дополняются пустым SII.

«Мин. область» — минимальная площадь островка в пикселях (по умолчанию 16,
0 отключает). Малые 4-связные области передаются сильнейшему окружающему
классу до гауссова размытия. Настройка может удалить реальные мелкие детали.
AUTO дополнительно выполняет два прохода пространственного согласования
неоднозначных пикселей с восемью соседями. Эти алгоритмы, включая HOO/SHO,
проверяются численным сравнением с JS 1.2. Палитра и минимальная площадь
сохраняются в настройках и проекте. Все расчёты поддерживают отмену.
